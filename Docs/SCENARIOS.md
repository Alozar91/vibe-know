## 1. Назначение и связь с документами

- Документ выполняет шаг [2] плана (CONCEPT.md, раздел 17): детальные пользовательские сценарии на основе утверждённых требований (Docs/REQUIREMENTS.md, ред. 1.0).
- Сценарии — основа приёмочной проверки функциональных требований: «требование считается выполненным, если поведение системы соответствует формулировке … по сценариям шага [2]» (REQUIREMENTS.md, раздел 7).
- Сценарии фиксируют **поведение системы** (шаги, данные, реакции, результаты), но не визуальный дизайн: UX/UI прорабатывается отдельным треком (16.1-33). Названия действий и разделов («Создать материал», «На проверку», «Мои материалы») — функциональные обозначения, а не решения об интерфейсе.
- Термины — по глоссарию концепции (CONCEPT.md, раздел 18). Ссылки: (FR-xxx), (NFR-xxx) — требования (REQUIREMENTS.md); (4.1) — разделы концепции; (16.1-xx) — решения концепции.
- Охват — только MVP; темы пост-MVP не сценарируются (реестр — CONCEPT.md 15.3).

| Обозначение | Кто это | Примечание |

## 3. Формат сценария и соглашения

Каждый сценарий содержит:

| Поле | Содержание |
|---|---|
| Актёры | Участники сценария (раздел 2) |
| Предусловия | Состояние системы и данных до начала |
| Трассировка | FR/NFR-требования и разделы концепции |
| Основной поток | Нумерованные шаги с ожидаемой реакцией системы |
| Ожидаемый результат | Итоговое состояние и проверяемые следствия |
| Альтернативные потоки | A1, A2, … — ошибки, отказы прав, граничные случаи |

Соглашения:

- Требуемое право на действие указано в сценарии; право проверяется на материале/группе с учётом наследования по цепочке (8.2, 8.5).
- «Видимый» материал/группа — по правилам видимости статусов (7.2) и отображения групп (8.2).
- Если действие недоступно по праву, элемент управления не отображается в интерфейсе; прямая попытка через API возвращает ошибку доступа, если сценарием не оговорено иное.
- Целевые значения отклика (NFR-001–NFR-007) приводятся в сценариях как принимаемые значения; методика проверок — раздел 4 REQUIREMENTS.md.
- Сценарии не задают визуальное оформление: формулировки «диалог», «предупреждение», «список» описывают поведение, а не макет.

## 4. Сценарии

### 4.1. Аутентификация и учётные записи

### US-001. Вход в систему

**Актёры:** Пользователь. **Трассировка:** FR-001, FR-004, FR-005, FR-011, FR-102; 13.2, NFR-018.
**Предусловия:** учётная запись создана СА в Keycloak (US-003).

**Основной поток:**
1. Пользователь открывает адрес системы — перенаправляется на страницу входа Keycloak.
2. Вводит логин и пароль; Keycloak проверяет учётные данные и выдаёт токены (OIDC).
3. Система сопоставляет пользователя по идентификатору из токена; пароли системой не хранятся (FR-001).
4. Открывается интерфейс на русском языке (NFR-018): дерево групп (US-005), разделы «Мои материалы», «На проверке», «Архив» (US-006), глобальный поиск в шапке (US-034).

**Ожидаемый результат:** вход выполнен; отображаются только объекты, доступные по правам (при отсутствии назначенных прав интерфейс пуст — default deny, FR-102).

**Альтернативные потоки:**
- **A1.** Неверный пароль: сообщение об ошибке; после 5 неудачных попыток подряд учётная запись блокируется на 15 минут (FR-004).
- **A2.** Учётная запись деактивирована: вход запрещён, ранее выданные токены не действуют (FR-011).
- **A3.** Сессия неактивна более 8 часов: при следующем действии требуется повторный вход (FR-005).

### US-002. Самостоятельный сброс забытого пароля

**Актёры:** Пользователь. **Трассировка:** FR-002, FR-003; 13.2, 11.3.
**Предусловия:** учётная запись существует; для основного потока — настроен SMTP (параметр системы).

**Основной поток:**
1. На странице входа пользователь выбирает «Забыли пароль?» и указывает учётную запись.
2. Keycloak отправляет ссылку сброса на email учётной записи.
3. Пользователь переходит по ссылке и задаёт новый пароль с соблюдением политики (FR-003).
4. Выполняет вход с новым паролем (US-001).

**Ожидаемый результат:** пароль изменён средствами Keycloak; система паролей не хранит.

**Альтернативные потоки:**
- **A1.** SMTP не настроен: самостоятельный сброс недоступен; пароль сбрасывает СА средствами Keycloak (FR-002).

### US-003. Заведение учётной записи и назначение ролей

**Актёры:** СА. **Трассировка:** FR-006, FR-007, FR-008, FR-009, FR-010, FR-105; 5.3.
**Предусловия:** СА аутентифицирован.

**Основной поток:**
1. СА создаёт учётную запись в Keycloak (имя, email); удаление учётных записей не предусмотрено (FR-006).
2. В системе (служебный раздел) СА назначает пользователю одну или несколько ролей-шаблонов — базовых или клонированных (FR-007, FR-008, FR-010; клонирование — FR-105).
3. При необходимости СА выдаёт права системной роли «Все пользователи» на конкретные объекты (например, чтение корневых групп) — права действуют для всех аутентифицированных (FR-009).
4. Пользователь выполняет вход (US-001) и видит объекты согласно правам.

**Ожидаемый результат:** учётная запись готова; автоназначение ролей при первом входе отсутствует (FR-009); составы шаблонов ролей — по 5.2 (редактируются СА, US-043).

**Альтернативные потоки:**
- **A1.** Пользователю не назначено ни одной роли и нет прав роли «Все пользователи»: вход возможен, интерфейс пуст (default deny).

### US-004. Деактивация учётной записи и передача права ревью

**Актёры:** СА. **Трассировка:** FR-011, FR-012, FR-139; 5.3.
**Предусловия:** существует активная учётная запись пользователя с материалами и/или правами.

**Основной поток:**
1. СА деактивирует учётную запись в Keycloak.
2. Система отзывает активные сессии и токены пользователя немедленно; вход запрещён (FR-011).
3. Служебный раздел показывает СА количество неархивированных материалов, где пользователь указан автором (FR-011); назначение «преемника» — организационно по регламенту внедрения (5.3, шаг [6]).
4. Если деактивированный — единственный носитель права «Ревью (утверждение)» в группе, в служебном разделе появляется задача «Передать право ревью»; её нельзя закрыть, пока право не назначено другому пользователю (US-044) (FR-012); остальная работа СА не блокируется.
5. Последствия: авторство и фиксация подписанта сохраняются; пользователь исключается из рассылок уведомлений (FR-139); его материалы остаются доступны другим согласно их правам.

**Ожидаемый результат:** материалы не «зависают» на ревью; данные не теряются.

**Альтернативные потоки:**
- **A1.** Носителей права ревью в группе несколько: требование передачи не возникает.

### 4.2. Навигация

### US-005. Дерево групп и списки материалов

**Актёры:** Пользователь. **Трассировка:** FR-103, FR-066, FR-117, FR-121, NFR-003, NFR-018; 8.2, 9.4.
**Предусловия:** пользователь аутентифицирован; структура групп создана СА (US-052).

**Основной поток:**
1. Пользователь открывает дерево групп. Группы с правом «Просмотр» (явным или унаследованным) отображаются с содержимым; промежуточные группы без права — только как путь навигации (дерево, хлебные крошки), без списка содержимого и действий (FR-103).
2. Пользователь выбирает видимую группу — открывается список её материалов: «Публикация»/«Архив» — все носители «Просмотр»; «Черновик»/«На проверке»/«Утверждён» — только участники процесса (автор; носители прав «Редактирование», «Удаление», «Ревью (утверждение)», «Публикация», «Архивация») и СА (FR-066).
3. Список по умолчанию отсортирован по дате последнего изменения (FR-117); страницы по 50 записей (FR-121); даты отображаются в часовом поясе браузера (NFR-018).
4. Выбор материала открывает карточку (US-037).

**Ожидаемый результат:** загрузка дерева групп и списков — p95 ≤ 2 с при пиковой нагрузке (NFR-003).

**Альтернативные потоки:**
- **A1.** Группа без права «Просмотр», но лежащая на пути к видимой подгруппе: отображается только названием-путём; содержимое и действия недоступны (FR-103).

### US-006. Разделы «Мои материалы», «На проверке», «Архив»

**Актёры:** Пользователь. **Трассировка:** FR-123, FR-124, FR-125, FR-087, FR-088; 15.1, 7.8.
**Предусловия:** пользователь аутентифицирован.

**Основной поток:**
1. «Мои материалы» — все неудалённые материалы, где пользователь указан автором, включая архивные; фильтрация — общими средствами списков; показываются независимо от права «Просмотр» на содержащие их группы (FR-123).
2. «На проверке» — материалы в статусе «На проверке», где пользователь — носитель права «Ревью (утверждение)» (на группе или материале); показываются независимо от права «Просмотр» на группы (FR-124).
3. «Архив» — архивные материалы, доступные по праву «Просмотр» (FR-125); редактирование запрещено (FR-087); раздел не зависит от фильтра поиска «Включая архив» (FR-088).

**Ожидаемый результат:** быстрая навигация участников процесса, не зависящая от прав на группы (15.1).

**Альтернативные потоки:**
- **A1.** Раздел без подходящих объектов: пустой список без ошибок.

### 4.3. Материалы: создание и правки

### US-007. Создание материала с файлом

**Актёры:** Пользователь с правом «Создание» в целевой группе. **Трассировка:** FR-024, FR-026, FR-027, FR-029, FR-030, FR-031, FR-048, FR-052, FR-057, FR-144, NFR-004; 4.2, 7.9.
**Предусловия:** право «Создание» на группу; нужный тип материала заведён (US-030).

**Основной поток:**
1. Пользователь выполняет действие «Создать материал» в группе.
2. Заполняет обязательные поля: название, тип, группа (предзаполнена текущей) (FR-026); длина названия — до 255 символов (параметр, FR-027).
3. Загружает файл размером до 100 МБ (FR-031).
4. Система обрабатывает текстовое представление по правилам: «текстовый файл» — файл с расширением .md/.txt либо mime-типом text/* (FR-029); для текстового файла при пустом текстовом представлении — автозаполнение содержимым файла (FR-029); для HTML автозаполнение не выполняется (FR-029).
5. Пользователь заполняет атрибуты (обязательные проверяются при сохранении, FR-048) и теги с автодополнением из словаря (FR-052).
6. Сохранение: материал создаётся в статусе «Черновик»; фиксируются автор, даты создания/изменения, статус, группа (FR-026); создаётся версия 1 (FR-144); файл ставится в очередь антивирусной проверки (US-011).

**Ожидаемый результат:** материал в «Черновике»; сохранение — p95 ≤ 2 с (NFR-004).

**Альтернативные потоки:**
- **A1.** Название совпадает с существующим неудалённым материалом группы (без учёта регистра и крайних пробелов; «е» и «ё» — разные буквы): создание блокируется с сообщением (FR-027).
- **A2.** Файл больше лимита: загрузка блокируется с понятным сообщением (FR-031).
- **A3.** Обязательный атрибут не заполнен: сохранение отклоняется с перечнем полей (FR-048).
- **A4.** Нет права «Создание»: действие недоступно; запрос через API — ошибка доступа.
- **A5.** Текстовый файл загружается в материал с непустым текстовым представлением: диалог «Обновить текстовое представление?» — при согласии текст заменяется, при отказе текст сохраняется и в карточке появляется признак «текстовое представление не синхронизировано с файлом» (снимается при обновлении текста) (FR-030, 16.1-110).

### US-008. Создание «пустышки» и последующая загрузка файла

**Актёры:** Пользователь с правом «Создание». **Трассировка:** FR-024, FR-028, FR-030, FR-076; 4.2, 7.5.
**Предусловия:** право «Создание» в группе.

**Основной поток:**
1. Пользователь создаёт материал без файла, заполняя название, тип, группу (FR-024).
2. Материал — в статусе «Черновик»; текстовое представление может быть заполнено вручную.
3. Пользователь пытается перевести материал в статус «На проверке» — переход отклоняется: файл отсутствует, текстовое представление его не заменяет (FR-028, FR-076).
4. Пользователь загружает файл: обработка как в US-007; при непустом текстовом представлении диалог предложения действует только для текстового файла (Markdown, TXT) — для нетекстовых форматов предложение не выдаётся (FR-030, 16.1-112).
5. После успешной антивирусной проверки файл доступен; материал может пройти жизненный цикл (US-015).

**Ожидаемый результат:** без файла материал остаётся в «Черновике» при любом тексте; «публикация только текстом» невозможна.

### US-009. Редактирование материала (по статусам)

**Актёры:** Носитель права «Редактирование» на материале; рецензент — на «На проверке». **Трассировка:** FR-027, FR-030, FR-041, FR-079, FR-084, FR-085, FR-087, FR-138, FR-144; 7.6, 7.7, 4.4.
**Предусловия:** материал существует; у пользователя есть право «Редактирование», либо материал в «На проверке» и пользователь — рецензент (неявное право, FR-079).

**Основной поток:**
1. **«Черновик»:** правка файла, текстового представления, названия, типа, атрибутов, тегов — статус сохраняется; при реальном изменении создаётся версия (FR-144); при замене текстового файла (Markdown, TXT) с непустым текстом — диалог обновления текстового представления; для нетекстовых форматов предложение не выдаётся (FR-030, 16.1-112).
2. **«На проверке»:** правка контента сохраняет статус (материал остаётся на ревью); автор и рецензенты получают уведомление «материал изменён на ревью», инициатор правки его не получает (FR-085, FR-138); факт правки фиксируется в аудите.
3. **«Утверждён»/«Публикация»:** правка контента (файл, текстовое представление) снимает утверждение и публикацию — материал возвращается в «Черновик», поле «подписант» очищается (FR-084); для мастера с подчинёнными в «Публикации» правка контента блокируется валидатором (FR-041, A1); правка только метаданных (название, тип, атрибуты, теги) статусы не снимает никогда (FR-084).
4. **«Архив»:** редактирование запрещено (FR-087).
5. После каждого сохранения обновляются «последний редактор» и дата изменения.

**Ожидаемый результат:** статусы изменяются строго по правилам 7.7; история — в версиях и аудите.

**Альтернативные потоки:**
- **A1.** Мастер с неудалёнными подчинёнными в статусе «Публикация»: правка контента блокируется валидатором смены статуса (иначе вернула бы мастера в «Черновик»); правка метаданных разрешена (FR-041, 4.4).
- **A2.** Версия материала неактуальна (параллельная правка): конфликт — US-010.
- **A3.** Пользователь без права «Редактирование» и не рецензент «На проверке»: действия недоступны; API — ошибка доступа.
- **A4.** Новое название конфликтует с существующим неудалённым материалом группы (без учёта регистра и крайних пробелов; «е» и «ё» — разные буквы): сохранение отклоняется с сообщением (FR-027).

### US-010. Конкурентное редактирование и смены статусов

**Актёры:** Два носителя права «Редактирование». **Трассировка:** FR-093, FR-094, FR-095; 7.11.
**Предусловия:** оба пользователя открыли один материал.

**Основной поток:**
1. Пользователь 1 сохраняет правку — успешно.
2. Пользователь 2 сохраняет свою правку от прежней версии — получает ошибку конфликта: версия материала неактуальна (оптимистичная блокировка, FR-093).
3. Пользователь 2 открывает актуальную версию и повторно вносит свои правки; слияние вручную, merge-интерфейса нет.
4. Смена статуса выполняется только от актуальной версии: если материал параллельно изменён или статус уже сменён, переход отклоняется ошибкой и повторяется пользователем (FR-094).

**Ожидаемый результат:** данные не теряются; конфликт разрешается вручную.

**Альтернативные потоки (API):**
- **A1.** Запрос без корректного `If-Match`/с устаревшим ETag: ошибка конфликта версий (FR-095); см. US-054.

### US-011. Антивирусная проверка загруженного файла

**Актёры:** Система; Пользователь (автор); СА. **Трассировка:** FR-057, FR-058, NFR-005, NFR-019; 13.2.
**Предусловия:** файл загружен в материал (US-007/US-008) и поставлен в очередь проверки.

**Основной поток:**
1. Система проверяет файл асинхронно отдельным процессом-сканером (на первом этапе — заглушка с тем же интерфейсом); тип файла определяется по содержимому, а не по расширению (FR-057).
2. До завершения проверки файл недоступен для предпросмотра и скачивания; карточка материала показывает состояние проверки (FR-058).
3. Проверка успешна (файл ≤ 100 МБ — не более 2 минут с момента постановки в очередь, NFR-005): файл становится доступен; материал не блокируется.
4. Результат проверки отражается в состоянии файла и наблюдается через мониторинг очередей (NFR-019); антивирусные события в аудит не включаются — перечень аудита закрыт (FR-140).

**Ожидаемый результат:** непроверенный файл недоступен; проверенный — доступен по правам.

**Альтернативные потоки:**
- **A1.** Обнаружено вредоносное содержимое: файл блокируется; автор и СА получают уведомление — прямое уведомление по FR-058, вне модели триггеров 11.1 (получатели фиксированы).
- **A2.** Создание подчинённого материала или копии из проверенного файла: повторная проверка не выполняется — содержимое идентично (FR-057); при замене файла проверка выполняется в общем порядке.

### US-012. Конвертация офисного формата и предпросмотр

**Актёры:** Пользователь с правом «Просмотр». **Трассировка:** FR-059, FR-060, NFR-006, NFR-014; 6.5.
**Предусловия:** DOCX/XLSX/PPTX загружен и прошёл антивирусную проверку.

**Основной поток:**
1. Система ставит файл в очередь конвертации в PDF (асинхронно, после антивируса).
2. До готовности PDF доступна карточка файла со скачиванием (по праву «Скачивание»); материал не блокируется (FR-060).
3. Конвертация завершена (файл ≤ 100 МБ — не более 10 минут, NFR-006): файл доступен в предпросмотре клиентским PDF-просмотрщиком; результат кэшируется.
4. Повторная конвертация — только при замене файла (FR-059).

**Ожидаемый результат:** офисные документы открываются в предпросмотре; отказ конвертера не приводит к потере данных (NFR-014).

**Альтернативные потоки:**
- **A1.** Ошибка конвертации: предпросмотр недоступен, скачивание работает, ошибка фиксируется в логах, материал не блокируется (FR-060).

### US-013. Предпросмотр по форматам

**Актёры:** Пользователь с правом «Просмотр». **Трассировка:** FR-055, FR-056, FR-061, FR-062, FR-063, FR-064, NFR-017; 6.2, 6.5.
**Предусловия:** материал виден пользователю; файл прошёл антивирусную проверку (US-011).

**Основной поток:**
1. PNG, JPG, Markdown, TXT отображаются нативно (FR-063).
2. SVG и HTML отображаются без скриптов (санитизация); встроенный HTML внутри Markdown вырезается/экранируется при рендере; PDF отображается без выполнения встроенного JavaScript (FR-061).
3. DOCX/XLSX/PPTX — через серверную конвертацию в PDF (US-012, FR-055).
4. Видео/аудио базового набора (MP4/H.264, WebM, MP3 и т.п.) стримятся с поддержкой Range-запросов — работает перемотка (FR-062).
5. Форматы, разрешённые СА сверх базового набора (настройка mime-типов): предпросмотра нет — только скачивание после антивируса (FR-056, FR-064).

**Ожидаемый результат:** предпросмотр работает в браузерах матрицы поддержки — последние две мажорные версии Chrome, Edge, Firefox (desktop) (NFR-017).

### US-014. Скачивание файла и текстового представления

**Актёры:** Носитель права «Скачивание». **Трассировка:** FR-067, FR-107, FR-140; 7.2, 8.6, 12.1.
**Предусловия:** материал виден пользователю (право «Скачивание» видимость не расширяет).

**Основной поток:**
1. Пользователь открывает карточку видимого материала — в любом статусе, включая «Архив» (FR-067).
2. Скачивает исходный файл (FR-067).
3. Скачивает текстовое представление отдельным файлом .md — независимо от наличия файла (FR-107, 16.1-108).
4. Система фиксирует в аудите факт скачивания файла и выгрузки текстового представления: кто, когда, какой объект (FR-140).

**Альтернативные потоки:**
- **A1.** Материал невидим пользователю (нет «Просмотр» и не участник процесса): прямая ссылка — ошибка доступа; операции недоступны (FR-067).
- **A2.** Текстовое представление пусто («пустышка» без текста): действие «скачать текст .md» недоступно (FR-107 — выгрузка текстового представления).

### 4.4. Жизненный цикл

### US-015. Отправка материала на проверку

**Актёры:** Носитель права «Редактирование» на материале (обычно автор). **Трассировка:** FR-028, FR-058, FR-071, FR-072, FR-075, FR-076, FR-078, FR-094, FR-138, NFR-007; 7.4–7.6, 11.1.
**Предусловия:** материал в статусе «Черновик», файл загружен и проверен антивирусом.

**Основной поток:**
1. Пользователь выполняет действие «На проверку».
2. Система проверяет: наличие файла (FR-076); файл доступен после успешной антивирусной проверки (FR-058); право «Редактирование» — предустановленное право перехода «Черновик → На проверке» (FR-071); актуальность версии (FR-094).
3. Статус меняется на «На проверке»; смена фиксируется в журнале статусов (кто, когда, из какого статуса в какой) и в аудите (FR-075).
4. Система создаёт уведомления всем рецензентам — носителям права «Ревью (утверждение)» на группе или на самом материале (FR-078); инициатор уведомление не получает (FR-138).

**Ожидаемый результат:** материал на ревью; рецензенты уведомлены (in-app ≤ 30 с, NFR-007).

**Альтернативные потоки:**
- **A1.** Файл отсутствует или не прошёл проверку: переход отклоняется с сообщением (FR-028, FR-058).
- **A2.** Нет права «Редактирование»: действие недоступно; переход без назначенного права недоступен никому, кроме СА (FR-072).
- **A3.** Версия неактуальна (параллельное изменение/переход): ошибка конфликта, повтор действия (FR-094).

### US-016. Утверждение материала рецензентом

**Актёры:** Рецензент (носитель права «Ревью (утверждение)»). **Трассировка:** FR-068, FR-070, FR-071, FR-075, FR-079, FR-083, FR-094, FR-138; 7.2, 7.4, 7.6.
**Предусловия:** материал в статусе «На проверке»; пользователь — рецензент материала.

**Основной поток:**
1. Рецензент открывает материал из раздела «На проверке» (US-006) или по уведомлению.
2. При необходимости рецензент редактирует материал — неявное право «Редактирование» в этом статусе; статус сохраняется (FR-079; правка — US-009, шаг 2); уведомление «изменён на ревью» инициатору правки не доставляется (FR-138).
3. Рецензент выполняет действие «Утвердить».
4. Система проверяет право перехода «На проверке → Утверждён» — «Ревью (утверждение)» (FR-071) и актуальность версии (FR-094).
5. Статус → «Утверждён»; фиксируются подписант и дата утверждения; финальный подписант — последний, выполнивший переход (FR-068); запись в журнале статусов и аудите (FR-075).

**Ожидаемый результат:** материал утверждён; подписант зафиксирован.

**Альтернативные потоки:**
- **A1.** Циклы ревью не ограничены (FR-083): материал может повторно отправляться на проверку и утверждаться; каждый переход — с фиксацией в журнале.

### US-017. Отклонение материала

**Актёры:** Рецензент. **Трассировка:** FR-071, FR-080, FR-138; 7.6.
**Предусловия:** материал в статусе «На проверке»; пользователь — рецензент.

**Основной поток:**
1. Рецензент выполняет действие «Отклонить» (право перехода — «Ревью (утверждение)», FR-071).
2. Комментарий при отклонении не обязателен (FR-080); при желании рецензент оставляет комментарий (US-038).
3. Статус → «Черновик»; автор получает уведомление «материал отклонён» (FR-080); инициатор не уведомляется (FR-138); запись в журнале статусов и аудите.

**Ожидаемый результат:** материал возвращён автору на доработку.

### US-018. Отзыв материала с ревью автором

**Актёры:** Носитель права «Редактирование» на материале. **Трассировка:** FR-081, FR-138; 7.6, 11.3.
**Предусловия:** материал в статусе «На проверке».

**Основной поток:**
1. Автор выполняет действие «Вернуть в черновик» (переход «На проверке → Черновик», право «Редактирование», FR-081).
2. Статус → «Черновик»; событие «отклонён» охватывает возвраты из «На проверке» (16.1-113), однако инициатор отзыва собственных уведомлений не получает (FR-081, FR-138); при расширении получателей администратором (US-047) отзыв доставляется им по общим правилам. Запись в журнале статусов и аудите.

**Ожидаемый результат:** материал снят с ревью без рассылки рецензентам.

### US-019. Отзыв утверждения

**Актёры:** Носитель права «Ревью (утверждение)». **Трассировка:** FR-082; 7.6, 7.7.
**Предусловия:** материал в статусе «Утверждён».

**Основной поток:**
1. Пользователь выполняет переход «Утверждён → Черновик» без правки контента (FR-082).
2. Поле «подписант» очищается (FR-082); история утверждения сохраняется в журнале статусов и аудите.
3. [решено, 16.1-113] Событие «отклонён» не создаётся: триггер (FR-134) охватывает только возвраты из статуса «На проверке» (отклонение, отзыв с ревью); отзыв утверждения фиксируется в журнале статусов и аудите без уведомлений.

**Альтернативные потоки:**
- **A1.** Отзываемый материал — мастер с подчинёнными в статусе «Утверждён»: отзыв создаёт состояние «подчинённый Утверждён, мастер — Черновик» — валидное, инвариантов не нарушает; публикация подчинённого блокируется до публикации мастера (FR-042), смена мастера подчинённого — только на материал в «Публикации» (FR-036); прямого уведомления авторам подчинённых нет — событие «мастер изменён» не определено для смен статуса (FR-038, критерий настройки).

### US-020. Публикация материала

**Актёры:** Носитель права «Публикация». **Трассировка:** FR-042, FR-066, FR-072, FR-073, FR-075, FR-086; 7.7, 4.4.
**Предусловия:** материал в статусе «Утверждён»; для подчинённого — мастер опубликован.

**Основной поток:**
1. Пользователь выполняет действие «Опубликовать» (защищённый переход: в «Публикация» — только из «Утверждён», FR-073).
2. Система фиксирует дату и пользователя, выполнившего публикацию (FR-086); запись в журнале статусов и аудите (FR-075).
3. Материал становится доступен для просмотра всем пользователям с правом «Просмотр» (FR-066); попадает в поиск и списки (US-034).

**Ожидаемый результат:** материал опубликован; источник публикации зафиксирован.

**Альтернативные потоки:**
- **A1.** Подчинённый материал при неопубликованном мастере: переход отклоняется с пояснением — подчинённый не может быть опубликован раньше мастера (FR-042).
- **A2.** Право «Публикация» отсутствует: действие недоступно (переход без права — только СА, FR-072).

### US-021. Архивация и каскадная архивация

**Актёры:** Носитель права «Архивация». **Трассировка:** FR-039, FR-041, FR-073, FR-087, FR-088, FR-134, FR-135, FR-138; 7.8, 4.4, 11.1, 16.1-116.
**Предусловия:** материал не в статусе «Архив».

**Основной поток (обычный материал):**
1. Пользователь выполняет действие «В архив» (защищённый переход «* → Архив» — из любого статуса, кроме «Архива», FR-073); подтверждение этой операции — решение UX-трека, требованием не установлено (16.1-33).
2. Статус → «Архив»; запись в журнале статусов и аудите.
3. Автор и подписант материала получают уведомление «материал заархивирован» (FR-134, FR-135, 16.1-116); инициатор уведомление не получает (FR-138), включая случай, когда инициатор — автор или подписант материала (анти-шум применяется ко всем триггерам).

**Основной поток (мастер-материал):**
4. Система показывает предупреждение: «Вместе с мастером будет заархивировано ещё N подчинённых материалов» (N — число неудалённых подчинённых) и требует подтверждения — подтверждение каскадной архивации установлено требованием FR-039, в отличие от одиночной (шаг 1).
5. После подтверждения все неудалённые подчинённые архивируются автоматически — независимо от их статуса и группы (FR-039); их авторы и подписанты получают уведомление «каскадная архивация» (FR-134, FR-135); инициатор уведомление не получает (FR-138); сам мастер уведомляет своих автора и подписанта триггером «материал заархивирован» (шаг 3, 16.1-116).

**Ожидаемый результат:** архив — финальный статус: разархивация невозможна (FR-087); архивные материалы доступны для просмотра (включая предпросмотр), скачивания и копирования; редактирование запрещено (FR-087); в поиске скрыты по умолчанию — включаются фильтром «Включая архив» (FR-088); доступны в разделе «Архив» (US-006).

**Альтернативные потоки:**
- **A1.** Мастер с подчинёнными в статусе «Публикация»: смена статуса на любой, кроме «Архив», блокируется валидатором (FR-041); переход «→ Архив» выполняется с каскадом по шагам 4–5.

### US-022. Обновление эталона с опубликованными адаптациями

**Актёры:** Носители прав «Архивация», «Копирование», «Создание», «Редактирование», «Ревью (утверждение)», «Публикация». **Трассировка:** FR-087, FR-089, FR-092; 7.8, 7.10.
**Предусловия:** мастер опубликован и имеет подчинённые материалы (адаптации).

**Основной поток:**
1. Архивация мастера с каскадом и предупреждением (US-021, FR-089).
2. Пользователь создаёт копию заархивированного мастера (US-028): так как мастер в архиве, копия становится самостоятельным материалом без `master_id` (FR-092).
3. Пользователь правит копию (US-009), отправляет на проверку, утверждение и публикацию (US-015, US-016, US-020) — новый эталон.
4. Пользователь создаёт новые подчинённые материалы нового эталона (US-024/US-025).

**Ожидаемый результат:** содержимое заархивированных адаптаций автоматически не переносится (FR-089); восстановление архивных материалов невозможно (FR-087) — старые адаптации остаются в архиве для истории.

### US-023. Удаление материала

**Актёры:** Носитель права «Удаление». **Трассировка:** FR-027, FR-040, FR-087, FR-090, FR-091; 7.9.
**Предусловия:** материал в статусе «Черновик» или «На проверке».

**Основной поток:**
1. Пользователь выполняет действие «Удалить» (подтверждение — решение UX-трека, требованием не установлено, 16.1-33).
2. Система проверяет статус — только «Черновик»/«На проверке» (FR-090).
3. Выполняется soft-delete: материал скрыт из дерева, списков и поиска, недоступен по прямой ссылке (FR-090); название освобождается — удалённые материалы не участвуют в проверке уникальности (FR-027).
4. Инварианты «использования» (подчинённые мастера, атрибуты, типы, теги) учитывают только неудалённые материалы (FR-091).
5. Операция фиксируется в аудите; просмотр удалённого — только СА в служебном разделе; восстановление запрещено (FR-090).

**Альтернативные потоки:**
- **A1.** Материал — мастер с неудалёнными подчинёнными: удаление запрещено с пояснением (FR-040).
- **A2.** Материал в статусе «Утверждён», «Публикация» или «Архив»: действие «Удалить» недоступно (только архивация, FR-090, FR-087).

### 4.5. Связь «мастер — подчинённый»

### US-024. Создание подчинённого материала (адаптация)

**Актёры:** Пользователь с правом «Создание» в целевой группе. **Трассировка:** FR-033, FR-035, FR-057, FR-108, FR-109, FR-126, NFR-010; 4.3, 8.6, 16.1-77.
**Предусловия:** мастер в статусе «Утверждён» или «Публикация» и виден пользователю; у пользователя есть право «Создание» в выбранной целевой группе.

**Основной поток:**
1. В карточке мастера пользователь выполняет действие «Создать подчинённый материал» (FR-126).
2. В диалоге выбирает вид «адаптация» (FR-033); имя по умолчанию — «<имя> Адаптация» (FR-035); выбирает целевую группу среди видимых ему групп (FR-109).
3. Система создаёт материал в статусе «Черновик»: физическая копия файла мастера, копии текстового представления, типа, атрибутов и тегов; копия логически независима — правки не затрагивают оригинал (FR-033); повторная антивирусная проверка не выполняется (FR-057); хранение дедуплицируется по хэшу содержимого (NFR-010). Право «Копирование» на мастере при этом не требуется (16.1-25): мастер в статусе «Утверждён»/«Публикация» уже прошёл контроль и адаптация под каналы — штатный сценарий; этим создание подчинённого отличается от копирования (US-028).
4. При конфликте имени в целевой группе система подставляет счётчик к полному имени: «<имя> Адаптация (2)», «<имя> Адаптация (3)», …; итоговое имя задаёт создатель (FR-035).
5. Устанавливается связь `master_id`; в карточке мастера подчинённый появляется в списке подчинённых (FR-126); подчинённый получает права от своей группы, не от мастера (8.2).

**Ожидаемый результат:** независимый черновик-адаптация со связью на мастера.

**Альтернативные потоки:**
- **A1.** Мастер не в статусе «Утверждён»/«Публикация» или невидим пользователю: действие недоступно/отклоняется (FR-033, 16.1-77).
- **A2.** Нет права «Создание» в целевой группе: создание отклоняется (FR-033, FR-108).

### US-025. Создание перевода

**Актёры:** Пользователь с правом «Создание» в целевой группе. **Трассировка:** FR-034, FR-035, FR-046, FR-122; 4.3, 6.1.
**Предусловия:** как в US-024; атрибут «Язык» входит в стартовый набор (FR-046), значения справочника заведены СА.

**Основной поток:**
1. В диалоге создания подчинённого пользователь выбирает вид «перевод» (FR-034).
2. Указывает язык из справочника: выбранное значение записывается в атрибут «Язык» нового материала (заменяя скопированное от мастера) и подставляется в имя по умолчанию — «<имя> (Перевод, <код языка>)» (FR-034, FR-035).
3. Далее — как US-024 (копия содержимого, статус «Черновик», связь с мастером).

**Ожидаемый результат:** перевод как подчинённый материал с заполненным атрибутом «Язык»; язык используется поиском (US-034, FR-122).

**Альтернативные потоки:**
- **A1.** Язык не указан: диалог не позволяет завершить создание перевода.
- **A2.** Тип материала не включает атрибут «Язык» (не назначен типу): значение записывается материалу независимо (16.1-115); в поиске участвует (FR-122); в карточке отображается в режиме «осиротевшего» значения, только чтение (FR-051).

### US-026. Смена мастера и отвязка от мастера

**Актёры:** Носитель права «Редактирование» на подчинённом материале. **Трассировка:** FR-032, FR-036, FR-108; 4.3, 4.4, 8.6, 16.1-111.
**Предусловия:** материал подчинённый; новый мастер соответствует условиям.

**Основной поток (смена мастера):**
1. Пользователь выполняет действие «Сменить мастера» и выбирает новый материал: новый мастер в статусе «Утверждён» или «Публикация» и виден пользователю (FR-036, FR-108).
2. Система проверяет ограничения модели: новый мастер не имеет собственного мастера (подчинённый не может быть мастером); циклы и ссылка на себя запрещены (FR-032).
3. Для подчинённого в статусе «Утверждён»/«Публикация» новый мастер — только в статусе «Публикация» (иначе нарушалось бы правило «подчинённый не публикуется до мастера») (FR-036).
4. Связь `master_id` обновляется; уведомление не создаётся: смена ссылки или отвязка не считаются изменением мастер-материала — событие «мастер изменён» (FR-038) не срабатывает (16.1-111).

**Основной поток (отвязка):**
5. Пользователь выполняет действие «Отвязать от мастера»: `master_id → NULL`, материал становится самостоятельным (FR-036).

**Ожидаемый результат:** связь изменена без нарушения инвариантов 4.4.

**Альтернативные потоки:**
- **A1.** Выбранный материал не соответствует условиям (статус, собственный мастер, видимость): выбор отклоняется с пояснением.

### US-027. Перемещение материала между группами

**Актёры:** Носитель прав «Перемещение» в обеих группах и «Редактирование» на материале. **Трассировка:** FR-037, FR-108, FR-109; 4.3, 8.6.
**Предусловия:** материал не является мастером с неудалёнными подчинёнными.

**Основной поток:**
1. Пользователь выполняет действие «Переместить» и выбирает целевую группу среди видимых (FR-109).
2. Если после перемещения материал станет недоступен работавшим с ним пользователям, система предупреждает об этом до подтверждения (FR-037).
3. Пользователь подтверждает операцию; система проверяет права («Перемещение» в исходной и целевой группах, «Редактирование» на материале, FR-037/FR-108) и уникальность названия в целевой группе.
4. Явные права материала сохраняются, наследование пересчитывается по новой цепочке групп (FR-037); связь с мастером не меняется.

**Ожидаемый результат:** материал в новой группе; права консистентны.

**Альтернативные потоки:**
- **A1.** Конфликт названия в целевой группе: операция отклоняется с ошибкой и требованием переименовать материал вручную; автопереименование не применяется (FR-037).
- **A2.** Материал — мастер с неудалёнными подчинёнными: перемещение недоступно (FR-037).

### US-028. Копирование материала

**Актёры:** Носитель права «Копирование» на исходном материале и «Создание» в целевой группе. **Трассировка:** FR-092, FR-108, FR-057; 7.10, 8.6.
**Предусловия:** исходный материал виден пользователю (любой статус, включая «Архив»).

**Основной поток:**
1. Пользователь выполняет действие «Копировать» и выбирает целевую группу среди видимых (FR-109).
2. Система создаёт материал в статусе «Черновик»: копии файла (без повторного антивируса, FR-057), текстового представления, типа, атрибутов и тегов (FR-092).
3. Имя по умолчанию — «<имя> Копия»; при конфликте — счётчик «X Копия (2)», «X Копия (3)», … (FR-092).
4. `master_id` копии сохраняется, если мастер исходного материала не в архиве; иначе копия — самостоятельный материал (FR-092).
5. Подчинённые материалы копируемого мастера не копируются (FR-092).

**Ожидаемый результат:** независимый черновик-копия; оригинал не изменяется.

### US-029. Уведомление «мастер изменён»

**Актёры:** Система; Автор/Редактор мастера; Автор/Подписант подчинённых. **Трассировка:** FR-038, FR-134, FR-135, FR-138, NFR-007; 4.4, 11.
**Предусловия:** у мастера есть неудалённые подчинённые материалы; критерий «изменения мастера» — настройка системы, по умолчанию «правка файла или текстового представления» (FR-038).

**Основной поток:**
1. Пользователь правит контент мастера (US-009, шаги 1–3 — правка контента в любом статусе; статусного ограничения у триггера нет).
2. Система фиксирует изменение (версия, «последний редактор», дата) и вычисляет событие «изменён мастер-материал» по настроенному критерию (FR-038); если правка контента в «Утверждён»/«Публикация» вернула материал в «Черновик» (FR-084), событие фиксируется после смены статуса; при включённом общем триггере «изменение статуса» специализированный триггер исключает дубли (FR-134).
3. Уведомление получают авторы и подписанты всех подчинённых материалов (FR-038; получатели по предустановленной конфигурации, FR-135); инициатор уведомление не получает (FR-138).
4. Повторные события по тому же материалу в окне доставки не создают новых уведомлений (анти-шум, FR-138).

**Ожидаемый результат:** доставка in-app ≤ 30 с, email ≤ 5 минут (NFR-007).

**Альтернативные потоки:**
- **A1.** Правка только метаданных мастера при критерии «(а) правка файла или текста»: событие не создаётся (FR-038); при критерии «(б) любое изменение» — создаётся.

### 4.6. Типы материалов, атрибуты, теги

### US-030. Управление типами материалов и атрибутами (СА)

**Актёры:** СА. **Трассировка:** FR-043, FR-044, FR-045, FR-050, FR-051, FR-140; 6.1.
**Предусловия:** СА аутентифицирован.

**Основной поток:**
1. СА создаёт атрибут в глобальном пуле: выбирает тип значения (строка, число, дата, ссылка URL, справочник), признак многозначности (для строк, ссылок, справочников), флаг «обязательный», порядок отображения в карточке (FR-044).
2. СА создаёт тип материала (например, «Описание препарата») и назначает на него атрибуты из пула — не более 50 на тип (параметр) (FR-044).
3. После создания атрибута тип значения и многозначность неизменяемы (FR-045); флаг «обязательный» изменяем и действует для последующих сохранений — существующие материалы не блокируются (FR-045).
4. Попытка удалить атрибут, используемый хотя бы одним неудалённым материалом, или тип, назначенный хотя бы одному неудалённому материалу, отклоняется (FR-050).
5. СА исключает атрибут из типа: значения не удаляются — сохраняются и отображаются в материалах в режиме «только чтение», участвуют в поиске; при возврате атрибута на тип снова становятся редактируемыми (FR-051).
6. Все операции фиксируются в аудите (FR-140).

**Ожидаемый результат:** структура типов и атрибутов настроена; инварианты использования соблюдены.

### US-031. Заполнение атрибутов и тегов в карточке материала

**Актёры:** Носитель права «Редактирование». **Трассировка:** FR-044, FR-047, FR-048, FR-051, FR-052; 6.1, 6.4.
**Предусловия:** тип материала назначен; атрибуты заведены (US-030); словарь тегов ведётся (US-033).

**Основной поток:**
1. В карточке материала атрибуты отображаются в заданном порядке.
2. Для атрибута типа «справочник» выбор — из выпадающего списка/автодополнением; свободный ввод запрещён (FR-047).
3. Многозначные атрибуты принимают список значений (несколько действующих веществ, терапевтических областей и т.п.) (FR-044).
4. Теги выбираются из глобального словаря с автодополнением; не более 20 на материал (параметр) (FR-052).
5. При сохранении система проверяет обязательные атрибуты (FR-048).

**Альтернативные потоки:**
- **A1.** «Осиротевшие» значения (атрибут исключён из типа): отображаются в режиме «только чтение», не редактируются (FR-051).

### US-032. Смена типа материала

**Актёры:** Носитель права «Редактирование». **Трассировка:** FR-041, FR-049, FR-051, FR-084; 6.1.
**Предусловия:** материал редактируем (статус и права — US-009).

**Основной поток:**
1. Пользователь меняет тип материала в карточке и заполняет обязательные атрибуты нового типа в том же сохранении (FR-049).
2. Сохранение проходит; значения атрибутов прежнего типа сохраняются и отображаются в режиме «только чтение» (FR-051).

**Альтернативные потоки:**
- **A1.** Обязательные атрибуты нового типа не заполнены: операция отклоняется с перечнем недостающих полей (FR-049).
- **A2.** Материал — мастер с подчинёнными в «Публикации»: смена типа (метаданные) разрешена — публикацию не снимает (FR-041, FR-084).

### US-033. Управление справочниками и словарём тегов (СА)

**Актёры:** СА. **Трассировка:** FR-047, FR-052, FR-053, FR-054, FR-140; 6.1, 6.4.
**Предусловия:** СА аутентифицирован.

**Основной поток:**
1. СА ведёт справочник (например, «Язык»): добавляет значения; свободный ввод значений пользователями запрещён (FR-047).
2. СА ведёт глобальный словарь тегов: создаёт теги; свободное создание тегов пользователями запрещено — только выбор с автодополнением (FR-052).
3. СА переименовывает и сливает теги (FR-053).
4. Удаление значения справочника отклоняется, пока его использует хотя бы один неудалённый материал (FR-047); тег удаляется, только если не используется ни одним неудалённым материалом (FR-054).
5. Операции фиксируются в аудите (FR-140).

### 4.7. Поиск

### US-034. Полнотекстовый поиск

**Актёры:** Пользователь. **Трассировка:** FR-110, FR-111, FR-112, FR-113, FR-114, FR-118, FR-121, FR-122, FR-127, NFR-001; 9.2–9.7.
**Предусловия:** пользователь аутентифицирован; материалы индексируются (название, системные метаданные, названия групп, атрибуты, теги, текстовое представление; содержимое файлов и комментарии — не индексируются, FR-111).

**Основной поток:**
1. Пользователь вводит запрос в глобальный поиск в шапке — доступен на всех страницах (FR-110).
2. Многословный запрос по умолчанию требует все слова (логика И); точная фраза — в кавычках (FR-113).
3. Переключателем включается частичное совпадение: «парацет» находит «Парацетамол» (триграммы pg_trgm) (FR-114).
4. Выдача содержит только материалы, доступные пользователю; все видимые статусы, кроме «Архива» (FR-112); участники процесса видят и «Черновик»/«На проверке»/«Утверждён».
5. Совпадения подсвечиваются (FR-118); выдача постранично по 50 записей (FR-121); сортировка — релевантность, название, дата последнего изменения, дата публикации (FR-117).
6. Язык материала берётся из атрибута «Язык»: не задан — русский; русские и английские материалы ищутся со стеммингом; языки вне конфигурации FTS — без стемминга (находятся частичными совпадениями) (FR-122).
7. Отклик выдачи — p95 ≤ 2 с при пиковой нагрузке (NFR-001); факт запроса и открытия материала учитывается агрегированно в аналитике поиска, без персональных данных (FR-127).

**Альтернативные потоки:**
- **A1.** Материалы без текстового представления (DOCX, PDF и т.п.) находятся только по названию, атрибутам и тегам (FR-111) — ключевой риск качества поиска, отслеживается долей покрытия текстом (FR-127).
- **A2.** Совпадение по «е»/«ё» не гарантируется (правила FTS-словаря и триграмм) (9.7, 16.1-76).
- **A3.** Запрос без результатов: пустая выдача; запрос попадает в аналитику «запросы без результатов» (FR-127).
- **A4.** Атрибут «Язык» у материала не заполнен (не заполнен при создании или исключён из типа, US-031 A1): материал ищется как русскоязычный — со стеммингом (FR-122).

### US-035. Фильтры и сортировка в поиске

**Актёры:** Пользователь. **Трассировка:** FR-088, FR-112, FR-115, FR-116, FR-117, FR-121; 9.4.
**Предусловия:** открыта выдача поиска (US-034).

**Основной поток:**
1. Пользователь применяет фильтры: тип материала; группа — вместе со всеми вложенными подгруппами; статус; автор (в т.ч. для передачи дел при деактивации, 5.3); диапазон дат публикации; атрибуты; теги; архив (FR-115).
2. Операторы фильтров по атрибутам: строка — точное совпадение и подстрока; число и дата — диапазон; ссылка — точное совпадение; справочник — выбор значения; многозначные — совпадение любого из значений (FR-116).
3. Несколько выбранных тегов — совпадение любого (ИЛИ) (FR-115).
4. Фильтр «Включая архив» добавляет архивные материалы в выдачу (FR-112, FR-088).
5. Сортировка переключается: релевантность, название, дата последнего изменения, дата публикации (FR-117); пагинация — 50 записей (FR-121).

**Ожидаемый результат:** выдача соответствует фильтрам; права учитываются на уровне материала (FR-112).

### US-036. Группы и связи «мастер — подчинённый» в результатах

**Актёры:** Пользователь. **Трассировка:** FR-119, FR-120, FR-112; 9.3, 9.5.
**Предусловия:** открыта выдача поиска (US-034).

**Основной поток:**
1. Совпадение с названием группы — группа показывается в отдельном блоке результатов; только группы с правом «Просмотр»; выбор открывает группу в дереве (FR-119).
2. Для найденного подчинённого материала отображается ссылка на мастера — только если мастер доступен пользователю; иначе ссылка скрывается (FR-120).
3. Для найденного мастера отображается список доступных ему подчинённых (FR-120).
4. Фильтр «только мастер-материалы / только подчинённые» сужает выдачу: «мастер-материалы» — материалы без `master_id` (включая самостоятельные без подчинённых), «подчинённые» — с заданным `master_id` (FR-120).
5. Если пользователю доступен только мастер, подчинённые в выдаче не показываются (FR-112).

### 4.8. Карточка материала и комментарии

### US-037. Просмотр карточки материала

**Актёры:** Пользователь, которому виден материал. **Трассировка:** FR-014, FR-026, FR-030, FR-067, FR-075, FR-126, FR-145, NFR-002; 4.2, 6.3, 12.2.
**Предусловия:** материал виден пользователю (статусная видимость 7.2 или участие в процессе).

**Основной поток:**
1. Пользователь открывает материал из списка, поиска или по ссылке; прямая ссылка на невидимый материал — ошибка доступа (FR-067).
2. Карточка отображает: название, тип, статус, группу, автора, подписанта, последнего редактора, даты создания/изменения/публикации/архивации (FR-026); подписант — пользователь, утвердивший материал (FR-014).
3. Блок связей: для подчинённого — ссылка на мастера; для мастера — список подчинённых; действие «Создать подчинённый материал» (FR-126).
4. При несинхронизированном текстовом представлении отображается признак «текстовое представление не синхронизировано с файлом» (FR-126, FR-030).
5. Доступные действия определяются правами и статусом: редактировать, на проверку, утвердить/отклонить, вернуть в черновик, опубликовать, в архив, удалить, копировать, переместить, скачать (файл и текст .md), комментировать.
6. Доступны блоки: файл с предпросмотром (US-013), текстовое представление, версии с журналом статусов (US-041; версии и журнал видны тем, кому виден материал, FR-145), комментарии (US-038).
7. Открытие карточки — p95 ≤ 1 с при пиковой нагрузке (NFR-002).

### US-038. Комментарии

**Актёры:** Участники процесса — автор и носители прав «Редактирование», «Ревью (утверждение)», «Публикация» на материале. **Трассировка:** FR-096, FR-097, FR-098, FR-111, FR-140; 7.6, 9.2, 12.1.
**Предусловия:** материал виден пользователю.

**Основной поток:**
1. Участник процесса добавляет комментарий к материалу (FR-098).
2. Комментарий виден всем, кому виден материал (FR-097).
3. Комментарий не редактируется и не удаляется; создание фиксируется в аудите (FR-096).
4. Комментарии не индексируются и в поиске не участвуют (FR-111).

**Альтернативные потоки:**
- **A1.** Пользователь видит материал, но не участник процесса (например, читатель): комментарии читает, добавить не может (FR-098).

### 4.9. Уведомления

### US-039. In-app уведомления

**Актёры:** Пользователь-получатель. **Трассировка:** FR-134, FR-135, FR-136, FR-137, FR-138, NFR-007; 11, 16.1-116.
**Предусловия:** пользователь — получатель хотя бы одного триггера; in-app канал активен всегда.

**Основной поток:**
1. Происходит событие по триггеру: «материал на проверке», «материал отклонён», «мастер изменён», «материал изменён на ревью», «материал заархивирован» (16.1-116), «каскадная архивация подчинённого»; общий триггер «изменение статуса» по умолчанию отключён (FR-134).
2. Уведомление появляется в ленте со счётчиком непрочитанных; доставка in-app ≤ 30 с с момента события (FR-137, NFR-007).
3. Пользователь открывает ленту и отмечает уведомления прочитанными — отметка индивидуальна для каждого пользователя (FR-137).
4. Инициатор события собственных уведомлений не получает (FR-138); повторные события по одному материалу в окне доставки группируются без создания новых уведомлений (FR-138).

**Ожидаемый результат:** срок хранения in-app событий — не меньше срока хранения аудита по соответствующим событиям (FR-137).

### US-040. Email-уведомления и дайджест

**Актёры:** Пользователь-получатель; СА. **Трассировка:** FR-136, FR-138, FR-139, FR-151, NFR-007, NFR-014, NFR-019; 11.3, 13.2.
**Предусловия:** в настройках системы указан SMTP-сервер.

**Основной поток:**
1. Событие по триггеру формирует email-уведомление; адрес — из кэша email учётной записи Keycloak (`users.email_cache`, заполняется из claim токена и сверки; адрес истины — Keycloak, 16.1-119); система не хранит второй «истинный» адрес (FR-151).
2. Доставка асинхронная, с ретраями и дедупликацией; email ≤ 5 минут с момента события (FR-136, NFR-007).
3. Массовые получатели (например, «все рецензенты группы») получают дайджест — периодическую сводку с настраиваемым интервалом (FR-138).
4. Деактивированные пользователи исключаются из рассылок (FR-139).

**Альтернативные потоки:**
- **A1.** SMTP не настроен: email-канал и email-алертинг мониторинга (NFR-019) отключены, работает только in-app; настройка SMTP при внедрении (шаг [6]) обязательна, если требуются email-канал или алертинг (FR-136; параметр «SMTP-сервер»).
- **A2.** Отказ SMTP: письма доставляются после восстановления (ретраи, NFR-014); потеря уведомления не приводит к потере данных системы.
- **A3.** У пользователя нет email в учётной записи Keycloak: email не отправляется, in-app доставляется (FR-151).

### 4.10. Версии

### US-041. Просмотр версий и сравнение

**Актёры:** Пользователь, которому виден материал. **Трассировка:** FR-075, FR-144, FR-145, FR-146, NFR-018; 12.2, 7.4.
**Предусловия:** у материала есть версии (создаются при сохранении с реальным изменением параметров или загрузке нового файла, FR-144).

**Основной поток:**
1. Пользователь открывает блок «Версии» карточки: список версий с датами и авторами; доступен и для архивных материалов; просмотр — тем, кому виден материал (FR-145).
2. Пользователь выбирает две соседние версии — сравнение: текстовое представление и метаданные с подсветкой различий; файл — признак «файл изменён в этой версии» (FR-146).
3. Рядом доступен журнал статусов: кто, когда, из какого статуса в какой (FR-075, FR-145); даты отображаются в часовом поясе браузера (NFR-018).
4. Версия позволяет увидеть прежние: файл, текстовое представление, название, тип, атрибуты, теги; `master_id` и права не версионируются (FR-144).

### US-042. Восстановление версии

**Актёры:** Носитель права «Редактирование». **Трассировка:** FR-041, FR-084, FR-085, FR-038, FR-087, FR-148; 12.2, 7.7, 4.4.
**Предусловия:** материал виден; у пользователя есть право «Редактирование» (и статус допускает правку — US-009).

**Основной поток:**
1. Пользователь выбирает старую версию и выполняет «Восстановить».
2. Система создаёт новую версию на её основе — отката отдельной операцией нет (FR-148).
3. Применяются правила правки контента: для материала в «Утверждён»/«Публикация» восстановление снимает утверждение и публикацию (возврат в «Черновик», подписант очищается) (FR-148, FR-084).
4. `master_id` при восстановлении не меняется (FR-148).
5. События уведомлений — как для правки контента (FR-148 применяет правила 7.7): в «На проверке» — «материал изменён на ревью» автору и рецензентам (FR-085, FR-138); для мастера с неудалёнными подчинёнными — «мастер изменён» по настроенному критерию (FR-038, если восстанавливались файл или текстовое представление).

**Альтернативные потоки:**
- **A1.** Материал — мастер с подчинёнными в статусе «Публикация»: восстановление блокируется валидатором смены статуса (вернуло бы мастера в «Черновик») (FR-148, FR-041).
- **A2.** Материал в статусе «Архив»: восстановление недоступно (редактирование запрещено, FR-087).

### 4.11. Права доступа и роли

### US-043. Управление шаблонами ролей (СА)

**Актёры:** СА. **Трассировка:** FR-008, FR-100, FR-105, FR-106, FR-140; 5.2, 5.3, 8.1, 8.4.
**Предусловия:** СА аутентифицирован.

**Основной поток:**
1. СА просматривает пять базовых шаблонов ролей (Читатель, Автор, Рецензент, Публикатор, Системный администратор) с составами прав по каталогу (5.2, FR-008).
2. СА редактирует составы шаблонов через UI (FR-008); клонирует роль — копирует набор прав от одной роли к другой (FR-105).
3. Правки шаблона не влияют на уже созданные снапшоты — они действуют только для будущих копирований (FR-100).
4. Изменения шаблонов фиксируются в аудите (FR-105, FR-140).

### US-044. Назначение прав на объект (снапшоты) (СА)

**Актёры:** СА. **Трассировка:** FR-099, FR-100, FR-102, FR-105, FR-106, FR-140; 8.1, 8.3, 8.4.
**Предусловия:** объект (группа или материал) существует; шаблон роли выбран.

**Основной поток:**
1. СА выбирает объект и выполняет «Скопировать права из шаблона»: на объект создаётся снапшот — копия набора прав шаблона (FR-100, FR-105).
2. Для каждого права снапшота задаётся состояние: Разрешить / Запретить / Не задано (FR-102).
3. Снапшот действует для всех пользователей, которым назначена эта роль (FR-100).
4. Права наследуются: материал ← группа ← вышестоящие группы; уровня «система» нет; личных прав нет (FR-099).
5. Изменения прав фиксируются в аудите (FR-105, FR-140).

**Альтернативные потоки:**
- **A1.** Право «Управление правами» назначается в снапшотах, но на MVP не действует: правами управляет только СА; делегирование — пост-MVP (FR-106).

### US-045. Проверка прав (сквозной сценарий)

**Актёры:** Система; Пользователь; СА. **Трассировка:** FR-099, FR-101, FR-102, FR-103, FR-104, FR-129; 8.1–8.5.
**Предусловия:** права назначены по US-044; проверяется доступ к материалу.

**Основной поток:**
1. При каждом обращении система собирает все явные правила по цепочке: материал → группа → вышестоящие группы — из снапшотов всех ролей пользователя (8.5).
2. Если найден хотя бы один явный Deny на любом уровне — доступ запрещён (Deny побеждает, FR-102).
3. Иначе, если найден хотя бы один Allow — доступ разрешён.
4. Если правил нет ни на одном уровне — доступ запрещён (default deny) (FR-102).
5. Наследование действует только по цепочке «группа → материал»; связь «мастер — подчинённый» права не наследует (FR-101).
6. Системный администратор действует в обход всех правил (FR-104).
7. Группа отображается с содержимым при праве «Просмотр» (явном или унаследованном), иначе — только как путь навигации (FR-103).

**Ожидаемый результат:** единообразное разрешение прав в интерфейсе и API (каждый API-запрос проверяет права, FR-129).

### 4.12. Администрирование

### US-046. Настройка матрицы переходов (СА)

**Актёры:** СА. **Трассировка:** FR-069, FR-070, FR-071, FR-072, FR-073, FR-074, FR-140; 7.4.
**Предусловия:** СА аутентифицирован.

**Основной поток:**
1. СА открывает матрицу переходов (checkbox в UI) с предустановленной при развёртывании конфигурацией: «Черновик → На проверке» — «Редактирование»; «На проверке → Утверждён» — «Ревью (утверждение)»; «На проверке → Черновик» — «Ревью (утверждение)» или «Редактирование»; «Утверждён → Черновик» — «Ревью (утверждение)»; «Утверждён → Публикация» — «Публикация»; «* → Архив» — «Архивация» (FR-071).
2. СА меняет права переходов: на переход назначается одно или несколько прав — достаточно любого из них (FR-070).
3. СА удаляет незащищённый переход: существующие материалы остаются в текущем статусе (FR-074).
4. Защищённые системные переходы нельзя удалить или обойти: в «Публикация» — только из «Утверждён»; в «Архив» — из любого статуса, кроме «Архива»; исходящие из «Архива» запрещены (FR-073); пользовательские статусы на MVP отсутствуют (FR-069).
5. Изменения матрицы фиксируются в аудите (FR-140).

**Ожидаемый результат:** переход без назначенного права недоступен никому, кроме СА (default deny, FR-072); новые правила применяются к последующим переходам.

### US-047. Настройка уведомлений (СА)

**Актёры:** СА. **Трассировка:** FR-038, FR-134, FR-135, FR-138, FR-140; 11.1, 11.2.
**Предусловия:** СА аутентифицирован.

**Основной поток:**
1. СА открывает настройки уведомлений в модели «триггер → типы получателей»; типы получателей: роль-шаблон, документный факт (автор, подписант, последний редактор), носители права (FR-135). Триггеры: «материал на проверке», «материал отклонён», «мастер изменён», «материал изменён на ревью», «материал заархивирован», «каскадная архивация подчинённого», общий «изменение статуса» (FR-134).
2. Предустановленная конфигурация: «на проверке» → рецензенты материала; «отклонён» → автор; «изменён на ревью» → автор и рецензенты; «мастер изменён» → авторы и подписанты подчинённых; «материал заархивирован» → автор и подписант материала (16.1-116); «каскадная архивация» → авторы и подписанты подчинённых (FR-135).
3. Общий триггер «изменение статуса» по умолчанию отключён; СА включает его с выбором типов получателей — специализированные триггеры имеют приоритет и исключают дубли (FR-134).
4. СА настраивает критерий «изменения мастера» (FR-038) и интервал дайджеста (FR-138).
5. Изменения фиксируются в аудите (FR-140).

### US-048. Параметры системы и mime-типы (СА)

**Актёры:** СА. **Трассировка:** FR-031, FR-038, FR-052, FR-056, FR-084, FR-121, FR-122, FR-140, FR-141, раздел 5 (REQUIREMENTS), NFR-020; 16.1-3.
**Предусловия:** СА аутентифицирован.

**Основной поток:**
1. СА просматривает и изменяет параметры без правки кода (NFR-020), значения по умолчанию — раздел 5 (REQUIREMENTS.md). В настройках системы: максимальный размер файла (100 МБ), состав языковых конфигураций FTS (русский + английский), критерий «изменения мастера», состав «контентных» параметров (файл, текстовое представление), срок хранения аудита, интервал дайджеста, SMTP, размер страницы (50), максимум тегов (20) и атрибутов (50), максимальная длина названия (255). В консоли Keycloak (FR-001, FR-006): тайм-аут сессии (8 ч), политика паролей, блокировка при переборе (5 → 15 мин).
2. СА расширяет список разрешённых к загрузке mime-типов: файлы вне базового набора доступны только для скачивания после антивируса, без предпросмотра (FR-056).
3. Изменения параметров фиксируются в аудите (FR-140).

### US-049. Аудит: просмотр и выгрузка (СА)

**Актёры:** СА. **Трассировка:** FR-140, FR-141, FR-142, FR-143; 12.1.
**Предусловия:** в системе накоплены события.

**Основной поток:**
1. СА открывает журнал аудита; записи содержат: кто, когда, что сделал, над каким объектом; охват — создание, редактирование, смены статусов, изменения прав, архивация, удаление, скачивание файлов и выгрузка текстового представления, создание комментариев, административные операции (группы, типы, атрибуты, справочники, теги, матрица переходов, настройки системы) (FR-140).
2. СА выгружает журнал в файл JSON для проверок и комплаенса; сама выгрузка фиксируется в аудите (FR-143).
3. Записи неизменяемы: правка и точечное удаление по запросу невозможны; очистка — только пакетным удалением по возрасту записей согласно настроенному сроку хранения (FR-141).
4. Просмотры материалов в аудит не входят — приватность и минимизация ПДн (FR-142).

**Предусловия:** существуют soft-deleted объекты.

**Основной поток:**
1. СА открывает служебный раздел и просматривает удалённые материалы и группы (FR-021, FR-090).
2. Восстановление запрещено — раздел только для просмотра (FR-021, FR-090).

### US-051. Аналитика поиска (СА)

**Актёры:** СА. **Трассировка:** FR-127; 9.9, 3.2.
**Предусловия:** накоплены агрегированные данные поиска.

**Основной поток:**
1. СА открывает аналитику в служебном разделе — простые списки на MVP: популярные запросы; запросы без результатов; агрегированный CTR открытия материала из выдачи; доля материалов с заполненным текстовым представлением (FR-127).
2. Персональные данные в отчётах не используются (FR-127).
3. Данные служат для измерения критериев успеха (3.2) и решения о запуске тем пост-MVP (автоизвлечение текста — приоритетный кандидат, 15.3).

### US-052. Управление группами (СА)

**Актёры:** СА. **Трассировка:** FR-015, FR-016, FR-017, FR-018, FR-019, FR-020, FR-021, FR-022, FR-023, FR-140; 4.1.
**Предусловия:** СА аутентифицирован.

**Основной поток:**
1. СА создаёт группу с обязательным названием (до 255 символов, параметр, FR-017); вложенность подгрупп не ограничена (FR-016).
2. Уникальность названия проверяется среди подгрупп вышестоящей группы (корневые — среди корневых): без учёта регистра и крайних пробелов, «е» и «ё» — разные буквы; дубликат блокируется (FR-017).
3. СА переименовывает группы (FR-015).
4. Удаление пустой группы (без подгрупп и материалов, включая удалённые) — физическое; перед удалением система предупреждает о назначенных на группу правах; записи прав удаляются вместе с группой (FR-018).
5. Удаление непустой группы — soft-delete всей ветки: подгруппы и материалы скрываются, материалы сохраняют статусы и становятся недоступны (FR-019).
6. Удаление ветки запрещено, если она содержит мастер-материал с неудалёнными подчинёнными вне ветки (FR-020).
7. Удалённые группы скрыты из дерева и поиска, недоступны по ссылке; просмотр — только СА (US-050); названия освобождаются (FR-021, FR-022).
8. Перенос подгрупп под другого родителя не предусмотрен — структура меняется только созданием, переименованием и удалением (FR-023).
9. Все операции фиксируются в аудите (FR-140).

**Альтернативные потоки:**
- **A1.** Попытка создать дубликат названия: блокировка с сообщением (FR-017).

### US-053. API-клиент: аутентификация и операции

**Актёры:** API-клиент (сервисная учётная запись). **Трассировка:** FR-013, FR-123, FR-128, FR-129, FR-130, FR-131, FR-132, FR-133, NFR-021; 10.
**Предусловия:** сервисная УЗ создана в Keycloak; ей назначены роли-шаблоны в системе (FR-013).

**Основной поток:**
1. Клиент получает токен в Keycloak (OAuth2/OIDC) и обращается к REST API; система проверяет токен и права для каждого запроса как для обычного пользователя (FR-128, FR-129).
2. Клиент выполняет операции над материалами: создание, чтение, правка (с версионной проверкой), смена статусов; ресурс материала включает `master_id`; операции «создать подчинённый материал» (с копированием файла мастера), смена мастера, отвязка, перемещение, копирование; представление мастера включает список подчинённых (FR-132).
3. Клиент выполняет поиск: один эндпоинт с параметром `search_type` (fulltext / vector / hybrid); на MVP реализуется fulltext, остальные значения зарезервированы; результаты учитывают права (FR-133).
4. Списковые операции поддерживают пагинацию, фильтрацию, сортировку (FR-131); API версионировано (FR-130); актуальные контракты OpenAPI поставляются вместе с системой (NFR-021).

**Альтернативные потоки:**
- **A1.** Недействительный токен или отсутствие прав: ошибка аутентификации/доступа; поведение соответствует US-045 (FR-129).
- **A2.** Материал создан/изменён сервисной УЗ: авторство (и подписант, если УЗ выполняла утверждение) фиксируются за сервисной УЗ (FR-013); уведомления, адресованные автору/подписанту — сервисной УЗ, не доставляются (FR-013); раздел «Мои материалы» сервисной УЗ показывает её материалы (FR-123).

### US-054. API: версионная проверка (ETag / If-Match)

**Актёры:** API-клиент. **Трассировка:** FR-094, FR-095; 7.11.
**Предусловия:** материал существует.

**Основной поток:**
1. Чтение материала возвращает представление с ETag (версия материала).
2. Клиент выполняет изменение (или смену статуса) с заголовком `If-Match` = актуальный ETag — операция выполняется.
3. При неактуальном ETag (параллельная правка или другой переход) — ошибка конфликта; клиент повторяет чтение и применяет правку к актуальной версии (FR-094, FR-095).

**Предусловия:** система под пиковой нагрузкой (100 одновременных пользователей, NFR-008); читатель знает тему искомого материала.

## 7. Критерии приёмки сценариев

- Сценарий считается пройденным, если основной поток и все применимые альтернативные потоки дают описанные результаты — на окружении, эквивалентном целевому (single-node, NFR-016), в браузерах матрицы поддержки (NFR-017).
- FR-требование считается проверенным, когда покрыто хотя бы одним пройденным сценарием (раздел 5); архитектурные и инфраструктурные требования — по разделу 6.
- Проверки выполняются под учётными записями с ролями из раздела 2; права формируются снапшотами ролей на объекты — личных прав нет (8.1).
- Расхождение поведения системы со сценарием или требованием фиксируется как замечание ревью; уточнение концепции — только через 16.1 концепции (REQUIREMENTS.md, раздел 7).
- Замеры НФТ выполняются по разделу 4 REQUIREMENTS.md; целевые значения приведены в сценариях как принимаемые.
