# MANUAL — Корпоративная база знаний (КБЗ)

Краткое введение в систему для разработчиков: что это, что умеет, как устроено.
Здесь только общая картина — нормативные документы лежат в `Docs/`, детали
развёртывания — в `deploy/README.md`, контракты API — в `Docs/LLD.md` §12.

> Статус: MVP (11-этапный план реализован). Демо-стенд: `http://merch-vibe.ru/know/`
> (вход через Keycloak; тестовая регистрация с выбором роли включена).

## 1. Что это

Корпоративная база знаний — веб-система для управления внутренними документами
компании (регламенты, инструкции, положения и т.д.) со строгим разграничением
доступа и управляемым жизненным циклом: документ пишется автором, проходит
ревью, утверждается подписантом, публикуется и в конце концов архивируется.
На каждом шаге система проверяет права, пишет аудит, рассылает уведомления и
держит историю версий.

Ключевая идея модели доступа: права выдаются **не пользователям напрямую**, а
через **роли-шаблоны на объекты** (группы и материалы), с наследованием вниз по
иерархии групп. Пользователь видит только то, что ему явно разрешено
(default deny) — включая результаты поиска.

Масштаб по проекту: до 500 пользователей, до 10 000 материалов, on-premise
(только Open Source), русский интерфейс.

## 2. Что умеет

| Подсистема | Возможности |
|---|---|
| **Структура** | Иерархия групп (дерево, вложенность); материалы внутри групп |
| **Материалы** | Файл + текстовое представление; тип материала (Регламент, Инструкция… — настраиваются); настраиваемые атрибуты (строка, число, дата, ссылка, справочник) из глобального пула; теги; комментарии |
| **Мастер–подчинённый** | Эталонный материал + подчинённые: **адаптации** (под канал публикации) и **переводы** (с атрибутом «Язык»). Подчинённый — физическая копия файла и атрибутики мастера со **своим** жизненным циклом |
| **Жизненный цикл** | Статусы: Черновик → На проверке → Утверждён → Публикация → Архив (финальный). Матрица переходов настраивается СА, каждый переход привязан к праву; защищённые системные переходы нельзя удалить. Подписант и дата фиксируются при утверждении |
| **Права** | 8 прав (просмотр, создание, редактирование, удаление, ревью, публикация, архивация, скачивание + перемещение/управление правами). Снапшоты: права роли-шаблона копируются на конкретную группу/материал и там редактируются независимо. Наследование группа → материал. Смена статуса меняет видимость (черновик видят только участники процесса, публикацию — все с правом «Просмотр») |
| **Роли** | Шаблоны: Читатель, Автор, Рецензент, Публикатор, Системный администратор (суперпользователь), + виртуальная «Все пользователи». Клонирование шаблонов — пост-MVP |
| **Поиск** | Полнотекстовый (PostgreSQL FTS, рус + англ словари), частичное совпадение (pg_trgm), поиск по названию, метаданным, атрибутам, тегам, названиям групп и содержимому. **Выдача фильтруется правами**. Аналитика запросов (популярные/безрезультатные/открытия) |
| **Файлы** | CAS-хранилище: объект адресуется sha256-хэшем (дедупликация); версии материала с историей; оптимистичная блокировка (ETag / If-Match); антивирус-заглушка (конвейер готов к реальному ClamAV); конвертация DOCX/XLSX/PPTX → PDF; предпросмотр в браузере (файлы не отдаются наружу — только авторизованный стриминг через API) |
| **Уведомления** | Триггеры (на проверке, отклонён, утверждён, опубликован, архив…) → получатели (роль-шаблон или документный факт: автор/ревьюер/подписант). Каналы: in-app + email (SMTP — при внедрении). Асинхронная доставка через очередь, с ретраями и анти-шумом |
| **Аудит** | Журнал всех значимых действий (кто/что/когда/с какого IP), просмотр и экспорт CSV — СА |
| **Администрирование** | Пользователи и роли, справочники, атрибуты и типы, матрица переходов, снапшоты прав, параметры системы, триггеры уведомлений, аналитика поиска, служебный раздел (soft-delete корзина) |

## 3. Технологии

| Слой | Технология |
|---|---|
| Backend | Python 3.15, FastAPI, SQLAlchemy + Alembic, Pydantic |
| Фоновые задачи | Celery (+beat в составе worker), брокер — Valkey |
| БД | PostgreSQL 18 — единое хранилище бизнес-данных, FTS (pg_trgm, tsvector) |
| Аутентификация | Keycloak 26 (OIDC: Authorization Code + PKCE для SPA, client credentials для сервисных УЗ, introspection на API) |
| Кэш/очереди | Valkey 9.1 (RESP-совместим с Redis) |
| Файлы | Silo (форк MinIO, S3 API) как бэкенд CAS; Gotenberg (LibreOffice headless) для конвертации в PDF |
| Frontend | React 19 + TypeScript, Vite, без UI-фреймворка (свой CSS) |
| Web/прокси | nginx 1.30: статика SPA, TLS-терминация, обратный прокси `/api` |
| Мониторинг | Prometheus 3 + Alertmanager + blackbox/node/postgres-exporters |
| Развёртывание | Docker Compose, single-node; бэкапы: pgBackRest (БД, WAL/PITR) + restic (файлы) |

## 4. Архитектура

```
                          ┌─────────────────────────────┐
 браузер ──── HTTP(S) ───►│ nginx  :80/:443             │
                          │  /          → статика SPA   │
                          │  /api/v1    → api:8000      │
                          │  /auth      → keycloak:8080 │ (TLS-схема)
                          └──────┬──────────────────────┘
                                 │
      ┌──────────────────────────┼───────────────────────────┐
      ▼                          ▼                           ▼
┌─────────────┐          ┌─────────────┐            ┌─────────────┐
│ api         │          │ worker      │            │ keycloak    │
│ (FastAPI)   │          │ (Celery+beat│            │ realm kb    │
│ миграции,   │          │ антивирус,  │            │ (postgres)  │
│ REST, права │          │ конвертация,│            └─────────────┘
│ introspection│         │ email, sync,│
└──────┬──────┘          │ cas_gc…)    │
       │                 └──────┬──────┘
       ▼                        ▼
┌─────────────────────────────────────┐   ┌────────────┐  ┌───────────┐
│ postgres 18 (БД kb + БД keycloak)   │   │ silo (S3)  │  │ gotenberg │
│ бизнес-данные, версии, аудит, FTS   │   │ CAS sha256 │  │ офис→PDF  │
└─────────────────────────────────────┘   └────────────┘  └───────────┘
       ▲                        ▲
       └──── valkey (кэш прав, брокер Celery) ────┘

 Prometheus-стек собирает метрики со всех сервисов; алерты → email СА.
```

**Поток данных файла:** загрузка → api считает sha256 → кладёт объект в silo →
запись в БД (версия материала) → Celery-задача: антивирус → (если офисный)
Gotenberg → PDF-кэш в silo → индексация текстового представления для FTS.
Скачивание/предпросмотр: браузер просит api, api стримит из silo с проверкой
права — файловые URL наружу не утекают.

**Проверка прав:** API для каждого запроса вычисляет эффективные права по
SQL-предикату (рекурсивное наследование по группам + снапшоты + владение
материалом + статус), кэширует в Valkey с инвалидацией при изменении прав.
Один и тот же предикат применяется и к выдаче списков, и к поиску.

**Аутентификация:** SPA редиректит в Keycloak (PKCE; на http-стендах fallback
на plain — `crypto.subtle` доступен только в secure context), получает токены
в память (не localStorage); api на каждый запрос делает introspection токена,
провижинит пользователя в БД при первом входе. Периодическая сверка с
Keycloak (`keycloak.sync`) обновляет деактивации и email-кэш.

## 5. Устройство репозитория

```
backend/                  FastAPI-приложение (uv)
  app/api/v1/             REST-эндпоинты (materials, groups, permissions,
                          search, lifecycle, files, notifications, admin…)
  app/use_cases/          Бизнес-логика по подсистемам (права, ЖЦ, версии,
                          поиск, уведомления); require_super — обход СА
  app/db/                 SQLAlchemy-модели + миграции Alembic (10 миграций)
  app/worker/             Celery-задачи и beat-расписание
  tests/                  pytest: юнит + API-тесты по сценариям US-001–055

frontend/                 SPA (React 19 + Vite)
  src/auth.ts             OIDC + PKCE, токены в памяти, API-клиент (Bearer,
                          problem+json, If-Match)
  src/App.tsx + *.tsx     Экраны: дерево групп, карточка материала, поиск,
                          права, матрица переходов, админка, уведомления

deploy/                   Развёртывание (см. deploy/README.md)
  docker-compose.yml      Весь стек; параметры — через .env (.env.example)
  nginx/                  Конфиг nginx, Dockerfile (сборка SPA внутри),
                          TLS-fallback (self-signed placeholder)
  keycloak/               realm-kb-test.json — импорт realm с сид-УЗ
  seed_demo.py            Идемпотентный сид демо-данных (6 пользователей,
                          6 групп, 9 материалов во всех статусах)
  cleanup.sql, silo-clean.sh   Полная чистка контента для пересева

Docs/                     Нормативные документы (см. §7)
```

Ключевые конвенции кода: имена таблиц/колей и коды ошибок — точно как в
LLD §2/§12.2; изменение прав и переходов — только через use_cases (аудит +
инвалидация кэша там); optimistic locking материалов — ETag/If-Match
(без него 428).

## 6. Как поднять и посмотреть

```bash
# локально (Docker Desktop должен быть запущен)
cd deploy
cp .env.example .env      # заполнить change-me (пароли, секреты)
docker compose up -d      # весь стек; api сам применит миграции
docker compose ps         # дождаться healthy
python seed_demo.py       # демо-данные (опционально)
```

UI — `http://localhost/` (или `http://localhost/know/` при `VITE_APP_BASE=/know`),
OpenAPI — `http://localhost:8001/api/v1/docs`, Prometheus — `:9090`.
Сид-пользователи: merch/ivanov (СА), petrov (Рецензент), sidorov (Автор),
smirnova (Читатель), kuznetsov (без роли — сценарий выбора роли).
Пароль — `KB_TEST_PASSWORD` из `.env`.

Подпуть `/know`: переменная `VITE_APP_BASE` меняет base сборки SPA и location
nginx. Схема стенда: `KB_PUBLIC_URL` (публичный адрес) + `KC_HOSTNAME_URL`
(issuer) задаются **до первого** `up` — realm импортируется один раз, смена
потом = `down -v` + пересев. TLS-схема (nginx `/auth`, закрытый 8080) — README §5.
